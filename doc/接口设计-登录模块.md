## 1. 通用约定

### 1.1 基础信息

| 约定项 | 说明 |
| --- | --- |
| 协议 | HTTP/1.1（生产环境建议 HTTPS） |
| 后端服务地址 | `http://localhost:8080` |
| 接口统一前缀 | `/api` |
| 前端访问方式 | 前端请求 `/api/**`，由 Vite 开发服务器代理到后端（见 `front/buptHepler/vite.config.js`），避免跨域 |
| 请求数据格式 | `application/json; charset=UTF-8` |
| 响应数据格式 | `application/json; charset=UTF-8` |
| 认证方式 | JWT，请求头 `Authorization: Bearer <token>` |
| 时间格式 | `yyyy-MM-dd HH:mm:ss` |
| 字段命名 | 小驼峰（camelCase） |

### 1.2 统一响应结构

所有接口（无论成功或失败）均返回如下结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 业务状态码，`0` 表示成功，其它值见 1.3 |
| message | string | 提示信息，中文，可直接展示给用户 |
| data | object \| array \| null | 业务数据；无返回数据时为 `null` |

### 1.3 业务状态码

| code | HTTP 状态码 | 含义 | 前端处理建议 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | 正常处理 `data` |
| 40001 | 400 | 请求参数校验失败 | 用 `data` 中的字段错误渲染表单项错误提示 |
| 40101 | 401 | 用户名或密码错误 | 表单顶部红色提示，不跳转 |
| 40102 | 401 | 未登录 / 登录已过期 | 清理本地 token，跳转登录页 |
| 40103 | 401 | 原密码错误 | 在“原密码”输入框提示 |
| 40301 | 403 | 无权限访问 | 跳转错误提示页 |
| 40401 | 404 | 用户不存在 | 提示信息 |
| 40901 | 409 | 用户名已存在 | 在“用户名”输入框提示 |
| 42901 | 429 | 登录失败次数过多，已临时锁定 | 提示剩余锁定时间 |
| 50000 | 500 | 服务器内部错误 | 通用错误提示 |

参数校验失败时，`data` 为字段名到错误信息的映射，便于前端逐字段标红：

```json
{
  "code": 40001,
  "message": "参数校验失败",
  "data": {
    "username": "用户名不能为空",
    "password": "密码至少包含 2 个数字"
  }
}
```

### 1.4 密码规则（全平台统一）

依据《需求说明.md》四.1：密码不少于 6 位、必须含有两个数字、不能都为大写或小写。落地为可校验的规则：

1. 长度 6 ~ 20 位；
2. 仅允许字母和数字；
3. 至少包含 **2 个数字**；
4. 至少包含 **1 个大写字母** 和 **1 个小写字母**（即不能全部为大写或全部为小写）。

对应正则：

```regex
^(?=(?:[^0-9]*[0-9]){2})(?=.*[a-z])(?=.*[A-Z])[A-Za-z0-9]{6,20}$
```

前端实现见 `front/buptHepler/src/utils/validate.js`，后端在注册、修改密码时须做同样的服务端校验。

### 1.5 手机号规则

11 位数字，以 1 开头，第二位为 3~9：`^1[3-9]\d{9}$`。

| user | UserVO | 登录用户信息 |

## 4. 接口详情

### 4.1 用户登录

`POST /api/auth/login`

- 鉴权：不需要
- 功能：校验用户名与密码，成功返回 JWT 令牌及用户信息

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 用户名，去除首尾空格后匹配，长度 1~50 |
| password | string | 是 | 登录密码，明文传输（生产环境走 HTTPS） |
| rememberMe | boolean | 否 | 是否“记住我”。`true`：令牌有效期 7 天；`false`：2 小时 |

**请求示例**

```http
POST /api/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "admin",
  "rememberMe": true
}
```

**成功响应**

```json
{
  "code": 0,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxIn0.xxxxx",
    "tokenType": "Bearer",
    "expiresIn": 604800,
    "user": {
      "userId": 1,
      "username": "admin",
      "userType": "ADMIN",
      "userTypeName": "系统管理员",
      "realName": "系统管理员",
      "phone": "13800000000",
      "bio": "系统内置管理员账号",
      "registerTime": "2026-01-01 09:00:00",
      "updateTime": "2026-01-01 09:00:00"
    }
  }
}
```

**失败场景**

| 场景 | HTTP | code | message |
| --- | --- | --- | --- |
| 用户名为空 | 400 | 40001 | 用户名不能为空 |
| 密码为空 | 400 | 40001 | 密码不能为空 |
| 用户名不存在或密码错误 | 401 | 40101 | 用户名或密码错误 |
| 连续失败 5 次 | 429 | 42901 | 登录失败次数过多，请 10 分钟后再试 |

**实现要求**

- 用户名不存在与密码错误返回同一提示，避免用户枚举；
- 登录成功后清空该账号的失败计数；
- 系统须内置一个管理员账号：`admin` / `admin`（《需求说明.md》三.1）。

### 4.2 用户注销

`POST /api/auth/logout`

- 鉴权：需要（`Authorization: Bearer <token>`）
- 功能：使当前令牌失效
- 请求体：无

**成功响应**

```json
{
  "code": 0,
  "message": "已退出登录",
  "data": null
}
```

**说明**

- 服务端可将令牌加入黑名单；若采用无状态 JWT，则返回成功即可，由前端清理本地令牌；
- 无论该接口成功与否，前端都要清理本地令牌与用户缓存并跳转登录页。

- 鉴权：需要
- 功能：根据令牌解析当前登录用户，用于刷新页面后恢复登录态、展示导航栏用户信息
- 请求参数：无

**成功响应**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "userId": 2,
    "username": "zhangsan",
    "userType": "USER",
    "userTypeName": "普通用户",
    "realName": "张三",
    "phone": "13912345678",
    "bio": "在校研究生，喜欢宠物",
    "registerTime": "2026-03-12 10:23:11",
    "updateTime": "2026-05-01 08:00:00"
  }
}
```

**失败场景**

| 场景 | HTTP | code | message |
| --- | --- | --- | --- |
| 未携带令牌 / 令牌非法 | 401 | 40102 | 请先登录 |
| 令牌已过期 | 401 | 40102 | 登录已过期，请重新登录 |
| 令牌对应用户已被删除 | 404 | 40401 | 用户不存在 |

### 4.4 用户注册

`POST /api/auth/register`

- 鉴权：不需要
- 功能：注册普通用户（`userType` 固定为 `USER`）

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 用户名，字母/数字/下划线，3~20 位，唯一 |
| password | string | 是 | 密码，规则见 1.4 |
| realName | string | 是 | 用户姓名，1~20 个字符 |
| phone | string | 是 | 手机号码，规则见 1.5 |
| bio | string | 否 | 用户简介，不超过 200 个字符 |

> `confirmPassword`（确认密码）仅由前端校验，不提交给后端。

**请求示例**

```json
{
  "username": "zhangsan",
  "password": "Zhangsan123",
  "realName": "张三",
  "phone": "13912345678",
  "bio": "在校研究生，喜欢宠物"
}
```

**成功响应**

```json
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "userId": 2,
    "username": "zhangsan",
    "userType": "USER",
    "userTypeName": "普通用户",
    "realName": "张三",
    "phone": "13912345678",
    "bio": "在校研究生，喜欢宠物",
    "registerTime": "2026-11-14 10:30:00",
    "updateTime": "2026-11-14 10:30:00"
  }
}
```

**失败场景**

| 场景 | HTTP | code | message |
| --- | --- | --- | --- |
| 用户名格式错误 | 400 | 40001 | 用户名为 3~20 位字母、数字或下划线 |
| 密码不符合规则 | 400 | 40001 | 密码至少包含 2 个数字 |
| 手机号格式错误 | 400 | 40001 | 请输入正确的 11 位手机号码 |
| 用户名已存在 | 409 | 40901 | 用户名已存在 |

**说明**

- 注册成功后前端跳转登录页并自动填入用户名，由用户手动登录（不自动签发令牌）；
- 注册时间与修改时间由服务端生成。

### 4.5 修改登录密码

`PUT /api/auth/password`

- 鉴权：需要
- 功能：登录用户修改自己的登录密码（《需求说明.md》二.3：仅可修改联系电话、用户简介、登录密码）

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| oldPassword | string | 是 | 原密码 |
| newPassword | string | 是 | 新密码，规则见 1.4，且不能与原密码相同 |

**请求示例**

```json
{
  "oldPassword": "Zhangsan123",
  "newPassword": "Lisi2024ABC"
}
```

**成功响应**

```json
{
  "code": 0,
  "message": "密码修改成功，请重新登录",
  "data": null
}
```

**失败场景**

| 场景 | HTTP | code | message |
| --- | --- | --- | --- |
| 原密码为空 | 400 | 40001 | 原密码不能为空 |
| 新密码不符合规则 | 400 | 40001 | 密码不能全部为大写或全部为小写 |
| 原密码错误 | 401 | 40103 | 原密码错误 |
| 新旧密码相同 | 400 | 40001 | 新密码不能与原密码相同 |

**说明**：修改成功后服务端应使旧令牌失效，前端清理本地令牌并跳转登录页。

---

### 4.6 校验用户名是否可用

`GET /api/auth/username-available?username=zhangsan`

- 鉴权：不需要
- 功能：注册页输入用户名失焦时实时校验，降低提交失败率

**请求参数**

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| username | query | string | 是 | 待校验的用户名 |

**成功响应**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "username": "zhangsan",
    "available": true
  }
}
```

**说明**：该接口仅作为友好提示，注册接口仍须在服务端做唯一性校验。

    ├── pages

### 5.2 令牌存放约定

| 存储位置 | key | 说明 |
| --- | --- | --- |
| localStorage | `bupt_helper_token` | 勾选“记住我”时使用，关闭浏览器仍保持登录 |
| sessionStorage | `bupt_helper_token` | 未勾选时使用，关闭标签页即失效 |
| localStorage | `bupt_helper_user` | 当前用户信息缓存，用于首屏快速渲染 |
| localStorage | `bupt_helper_remembered_username` | 上次登录的用户名，用于回填 |

> 令牌仅注入到 `Authorization` 请求头，绝不拼接到 URL 中。

### 5.3 请求封装约定（request.js）

1. 统一前缀 `/api`，可用环境变量 `VITE_API_BASE_URL` 覆盖；
2. 自动携带 `Authorization: Bearer <token>`，可通过 `auth: false` 关闭；
3. 解析统一响应体，`code === 0` 时返回 `data`，否则抛出 `ApiError(code, message, details)`；
4. HTTP 401 或 `code === 40102` 时清理本地令牌并回调未登录处理器（跳转登录页）；
5. 请求超时（默认 15 秒）与网络异常统一转换为带中文提示的 `ApiError`。

### 5.4 页面行为

| 页面 | 行为 |
| --- | --- |
| 登录页 `index.html` | 进入时若本地存在令牌则调用 `/auth/me` 校验，通过后跳转 `home.html`；表单校验通过后调用登录接口，成功保存令牌并跳转；支持 `?username=` 回填与 `?redirect=` 回跳 |
| 注册页 `register.html` | 前端校验全部字段（含确认密码一致性），用户名失焦时调用可用性校验；成功后跳转登录页并回填用户名 |
| 首页 `home.html` | 进入时校验登录态，展示当前用户信息与用户类型，提供退出登录入口 |

## 6. 安全与后端实现建议

1. 密码使用 BCrypt 加密存储，禁止明文与可逆加密；
2. 登录失败计数：同一用户名连续失败 5 次锁定 10 分钟（对应 42901）；
3. JWT 使用 HS256 签名，密钥放入配置项（如 `application.properties` 的 `bupthelper.jwt.secret`），不得硬编码在代码仓库中；
4. 令牌建议携带 `sub`（userId）、`username`、`type`（userType）、`exp`；
5. 所有接口对入参做服务端校验，不能只依赖前端校验；
6. 日志不得记录密码、令牌明文；
7. 初始化数据：至少内置 `admin` / `admin` 管理员账号（《需求说明.md》三.1）。

### 7.4 令牌失效策略

JWT 本身无状态，服务端通过内存登记表 `TokenRevocationStore` 实现失效：

- `POST /api/auth/logout`：登记该令牌的 `jti`，该令牌立即失效；
- `PUT /api/auth/password`：递增该用户的令牌版本号（令牌中的 `ver` 声明），此前签发的所有令牌全部失效。

> 该实现为单机内存版：重启后版本号归零，此前签发的令牌随之失效。多实例部署时应替换为 Redis 等共享存储。

### 7.5 运行方式

```bash
cd back/buptHelper
mvn spring-boot:run
# 或
mvn -DskipTests package && java -jar target/buptHelper-0.0.1-SNAPSHOT.jar
```

前端执行 `npm run dev` 后，Vite 会把 `/api` 代理到 `http://localhost:8080`。
