## 1. 通用约定

### 1.1 基础信息

| 约定项 | 说明 |
| --- | --- |
| 协议 | HTTP/1.1（生产环境建议 HTTPS） |
| 后端服务地址 | `http://localhost:8080` |
| 接口统一前缀 | `/api` |
| 前端访问方式 | 前端请求 `/api/**`，由 Vite 开发服务器代理到后端（见 `front/buptHepler/vite.config.js`） |
| 请求数据格式 | `application/json; charset=UTF-8`；文件上传为 `multipart/form-data` |
| 响应数据格式 | `application/json; charset=UTF-8`；附件内容接口返回二进制流 |
| 认证方式 | JWT，请求头 `Authorization: Bearer {token}`（附件内容接口除外） |
| 时间格式 | `yyyy-MM-dd HH:mm:ss` |
| 字段命名 | 小驼峰（camelCase） |
| 分页页码 | 从 **1** 开始 |

### 1.2 统一响应结构

与登录模块一致：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 1.3 业务状态码

在登录模块已有状态码基础上新增本模块状态码，前端按 `message` 直接提示。

| code | HTTP 状态码 | 含义 | 前端处理建议 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | 正常处理 `data` |
| 40001 | 400 | 请求参数校验失败 | 用 `data` 中的字段错误渲染表单项错误提示 |
| 40002 | 400 | 文件类型或大小不符合要求 | 在附件区域提示 |
| 40102 | 401 | 未登录 / 登录已过期 | 清理本地 token，跳转登录页 |
| 40302 | 403 | 只能操作自己发布的需求 | 顶部提示，返回列表 |
| 40402 | 404 | 需求不存在 | 显示错误提示页 |
| 40403 | 404 | 响应信息不存在 | 提示后刷新列表 |
| 40404 | 404 | 文件不存在 | 提示附件不可用 |
| 40902 | 409 | 该需求已有“我来也”响应，不能修改 | 表单顶部提示，返回详情 |
| 40903 | 409 | 该需求已有“我来也”响应，不能删除 | 确认框后提示删除失败 |
| 40904 | 409 | 当前响应状态不允许该操作 | 提示并刷新响应列表 |
| 40905 | 409 | 该需求已接受其他“我来也”响应 | 提示并刷新响应列表 |
| 40906 | 409 | 该需求已取消，不能进行该操作 | 提示并刷新详情 |
| 40907 | 409 | 文件已被需求引用，不能删除 | 忽略即可（清理性质操作） |
| 42901 | 429 | 操作过于频繁（预留） | 提示稍后再试 |
| 50000 | 500 | 服务器内部错误 | 通用错误提示 |

参数校验失败示例：

```json
{
  "code": 40001,
  "message": "参数校验失败",
  "data": {
    "title": "请输入需求主题",
    "description": "需求描述不能超过 1000 个字符"
  }
}
```

### 1.4 分页数据结构

所有分页接口的 `data` 均为 `PageResult<T>`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| list | array | 当前页数据 |
| page | int | 当前页码，从 1 开始 |
| pageSize | int | 每页条数 |
| total | long | 满足条件的总条数 |
| totalPages | int | 总页数（`total` 为 0 时为 0） |
| hasPrev | boolean | 是否存在上一页 |
| hasNext | boolean | 是否存在下一页 |

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [],
    "page": 1,
    "pageSize": 10,
    "total": 0,
    "totalPages": 0,
    "hasPrev": false,
    "hasNext": false
  }
}
```

### 1.5 字典与枚举

**帮忙类型**（`help_type` 表，前端显示 `typeName`）：

| typeCode | typeName |
| --- | --- |
| TOUR_GUIDE | 导游 |
| SHOPPING | 代购 |
| PET_CARE | 宠物代管 |
| PLANT_CARE | 绿植代培 |
| HOSPITAL_CARE | 住院陪护 |
| OTHER | 其他 |

**需求状态**（`help_request.status`）：

| status | statusName | 说明 |
| --- | --- | --- |
| 0 | 已发布 | 正常状态，可被响应 |
| -1 | 已取消 | 用户删除后置为该状态，仅可查看 |

**响应状态**（`help_response.status`）：

| status | statusName | 说明 |
| --- | --- | --- |
| 0 | 待接受 | 响应刚提交，等待需求发布者处理 |
| 1 | 同意 | 发布者接受该响应 |
| 2 | 拒绝 | 发布者拒绝该响应 |
| 3 | 取消 | 响应者主动撤回（“我来也”模块使用） |

### 1.6 附件上传约定

| 约定项 | 说明 |
| --- | --- |
| 上传方式 | `multipart/form-data`，表单字段名固定为 `file` |
| 图片格式 | `image/jpeg`、`image/png`、`image/webp`、`image/gif` |
| 视频格式 | `video/mp4`、`video/webm` |
| 图片大小 | 单张 ≤ 5MB，每条需求最多 6 张 |
| 视频大小 | 单个 ≤ 100MB，每条需求最多 1 个 |
| 附件总数 | 每条需求最多 7 个 |
| 展示顺序 | 按 `attachmentIds` 顺序展示，首个图片作为列表封面（`coverUrl`） |
| 内容访问 | `GET /api/files/{fileId}/content`，**无需 JWT**（`<img>` / `<video>` 无法附加请求头），文件名使用 UUID 防止枚举 |
| 临时文件 | 上传后未绑定需求的文件为“临时文件”，仅上传者可删除；服务端应定期清理超过 24 小时的临时文件 |

### 1.7 权限矩阵

| 操作 | 需求发布者 | 其他登录用户 | 管理员 |
| --- | --- | --- | --- |
| 查询自己发布的需求（`scope=mine`） | ✅ | ✅（结果为空） | ✅（结果为空） |
| 查询全部需求（`scope=all`） | ✅ | ✅ | ✅ |
| 查看需求详情 | ✅ | ✅ | ✅ |
| 发布需求 | ✅ | ✅ | ✅ |
| 修改 / 删除需求 | ✅（仅状态 0 且无响应） | ❌ 40302 | ❌ 40302 |
| 查看某需求的响应列表 | ✅ | ❌ 40302 | ✅ |
| 接受 / 拒绝响应 | ✅（仅自己的需求） | ❌ 40302 | ❌ 40302 |
| 上传附件 | ✅ | ✅ | ✅ |

> 说明：需求状态为 -1，或已存在任意“我来也”响应时，发布者也不能修改、删除（对应 40902 / 40903 / 40906）。

| 字段 | 类型 | 说明 |

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| fileId | long | 文件标识 |
| fileName | string | 原始文件名 |
| mediaType | string | `IMAGE` / `VIDEO` |
| contentType | string | MIME 类型 |
| size | long | 文件大小（字节） |
| url | string | 访问地址，形如 `/api/files/12/content` |
| sortNo | int | 排序号 |

### 2.4 RequestSummaryVO（需求列表项）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| requestId | long | 需求标识 |
| title | string | 需求主题 |
| typeCode | string | 帮忙类型编码 |
| typeName | string | 帮忙类型中文名称 |
| regionId | long | 地域标识 |
| regionName | string | 地域名称 |
| regionFullName | string | 地域全称（省 · 市 · 区） |
| status | int | 0 已发布 / -1 已取消 |
| statusName | string | 状态中文名称 |
| coverUrl | string \| null | 封面图地址（首个图片），无图片时为 `null` |
| imageCount | int | 图片数量 |
| videoCount | int | 视频数量 |
| responseCount | int | 收到的“我来也”响应总数 |
| pendingResponseCount | int | 待接受响应数 |
| acceptedResponseCount | int | 已接受响应数 |
| canModify | boolean | 当前登录用户能否修改（发布者本人 + 状态 0 + 无响应） |

| createTime | string | 创建时间 |
| updateTime | string | 修改时间 |

### 2.5 RequestDetailVO（需求详情）

包含 `RequestSummaryVO` 的全部字段，另加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| description | string | 需求描述 |
| mine | boolean | 当前登录用户是否为发布者 |
| publisher | UserBriefVO | 发布者信息 |
| attachments | AttachmentVO[] | 图片 / 视频附件，按 `sortNo` 升序 |

### 2.6 ResponseVO（“我来也”响应）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| responseId | long | 响应标识 |
| requestId | long | 需求标识 |
| responder | UserBriefVO | 响应者信息 |
| description | string | 响应描述 |
| attachments | AttachmentVO[] | 响应图片 / 视频 |
| status | int | 0 待接受 / 1 同意 / 2 拒绝 / 3 取消 |
| statusName | string | 状态中文名称 |
| canAccept | boolean | 当前用户能否接受（需求发布者 + 响应待接受 + 需求已发布 + 尚无已接受响应） |
| canReject | boolean | 当前用户能否拒绝（需求发布者 + 响应待接受） |
| canModify | boolean | 响应者能否修改（响应待接受，供“我来也”模块使用） |
| canDelete | boolean | 响应者能否删除（响应待接受，供“我来也”模块使用） |
| createTime | string | 提交时间 |
| updateTime | string | 修改时间 |

| 字段 | 类型 | 说明 |

| username | string | 用户名 |

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| userId | long | 用户标识 |
| username | string | 用户名 |

| bio | string | 用户简介 |

## 4. 接口详情

### 4.1 帮忙类型字典

`GET /api/requests/types`

- 鉴权：需要
- 功能：返回全部帮忙类型，供发布表单与筛选下拉框使用

**成功响应**

```json
{
  "code": 0,
  "message": "success",
  "data": [
    { "typeCode": "TOUR_GUIDE", "typeName": "导游", "sortNo": 1 },
    { "typeCode": "SHOPPING", "typeName": "代购", "sortNo": 2 },
    { "typeCode": "PET_CARE", "typeName": "宠物代管", "sortNo": 3 },
    { "typeCode": "PLANT_CARE", "typeName": "绿植代培", "sortNo": 4 },
    { "typeCode": "HOSPITAL_CARE", "typeName": "住院陪护", "sortNo": 5 },
    { "typeCode": "OTHER", "typeName": "其他", "sortNo": 99 }
  ]
}
```

**说明**：前端按 `sortNo` 升序展示；结果可缓存（如 10 分钟）。

### 4.2 地域字典

`GET /api/regions`

- 鉴权：需要
- 功能：返回全部地域，前端按 `province` 分组展示为 `<optgroup>`

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| province | string | 否 | 按省份过滤，模糊匹配 |

**成功响应**

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "regionId": 1,
      "regionName": "海淀区",
      "city": "北京市",
      "province": "北京市",
      "displayName": "北京市 · 北京市 · 海淀区"
    },
    {
      "regionId": 2,
      "regionName": "朝阳区",
      "city": "北京市",
      "province": "北京市",
      "displayName": "北京市 · 北京市 · 朝阳区"
    }

```

**说明**：

1. 前端展示中文名称，禁止展示 `regionId`；
2. 如未提供 `displayName`，前端会退化为 `city · regionName`，因此后端应始终返回该字段。

### 4.3 分页查询需求

`GET /api/requests`

- 鉴权：需要
- 功能：
  - `scope=mine`：查询当前登录用户发布的所有需求（“请帮忙”模块默认视图）；
  - `scope=all`：查询平台全部已发布需求（“好帮手信息查询”“我来也”模块使用）。

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| scope | string | 否 | `mine`（默认）/ `all` |
| status | int | 否 | `0` 已发布 / `-1` 已取消；不传表示全部。`scope=all` 时强制只返回 0 |
| typeCode | string | 否 | 帮忙类型编码，须存在于字典 |
| regionId | long | 否 | 地域标识 |
| keyword | string | 否 | 关键词，长度 ≤ 50，匹配 `title` 或 `description`（模糊） |
| page | int | 否 | 页码，默认 1，最小 1 |
| pageSize | int | 否 | 每页条数，默认 10，范围 1~50 |
| sort | string | 否 | 排序，格式 `字段,方向`；字段 `createTime`（默认）/ `updateTime`，方向 `desc`（默认）/ `asc` |

**请求示例**

```http
GET /api/requests?scope=mine&status=0&typeCode=SHOPPING&regionId=1&keyword=快递&page=1&pageSize=10&sort=createTime,desc
Authorization: Bearer {token}
```

**成功响应**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [
      {
        "requestId": 12,
        "title": "帮忙取一下快递",
        "typeCode": "SHOPPING",
        "typeName": "代购",
        "regionId": 1,
        "regionName": "海淀区",
        "regionFullName": "北京市 · 北京市 · 海淀区",
        "status": 0,
        "statusName": "已发布",
        "coverUrl": "/api/files/31/content",
        "imageCount": 2,
        "videoCount": 0,
        "responseCount": 2,
        "pendingResponseCount": 1,
        "acceptedResponseCount": 1,
        "canModify": false,
        "canDelete": false,
        "createTime": "2026-11-14 09:30:00",
        "updateTime": "2026-11-14 09:30:00"
      }
    ],
    "page": 1,
    "pageSize": 10,
    "total": 1,
    "totalPages": 1,
    "hasPrev": false,
    "hasNext": false
  }
}
```

**失败场景**

| 场景 | HTTP | code | message |
| --- | --- | --- | --- |
| 页码小于 1 / pageSize 超出范围 | 400 | 40001 | 参数校验失败 |
| 未登录 | 401 | 40102 | 请先登录 |

**实现要求**

1. 仅统计 `help_request.status IN (0, -1)` 的数据，不返回物理删除记录（本模块不做物理删除）；
2. `scope=mine` 以当前用户 `publish_user_id` 过滤；管理员使用 `scope=mine` 同样只返回自己发布的数据；
3. 响应数、待接受数、已接受数可通过 `help_response` 聚合，避免 N+1 查询；
4. `canModify` / `canDelete` 由服务端计算，前端不自行推导；
5. 排序字段必须白名单校验，禁止拼接原生 SQL 片段。

### 4.5 发布需求

`POST /api/requests`

- 鉴权：需要
- 功能：发布一条“请帮忙”需求，状态置为 0，并把已上传的附件绑定到该需求

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| title | string | 是 | 需求主题，去除首尾空格后 1~50 字符 |
| typeCode | string | 是 | 帮忙类型编码，须存在于字典 |
| regionId | long | 是 | 地域标识，须存在 |
| description | string | 是 | 需求描述，去除首尾空格后 1~1000 字符 |
| attachmentIds | long[] | 否 | 附件标识数组，顺序即展示顺序；图片 ≤ 6、视频 ≤ 1、总数 ≤ 7；仅可绑定本人上传且未绑定的文件 |

**请求示例**

```http
POST /api/requests
Content-Type: application/json
Authorization: Bearer {token}

{
  "title": "帮忙取一下快递",
  "typeCode": "SHOPPING",
  "regionId": 1,
  "description": "11 月 15 日 10:00-12:00 到菜鸟驿站取一个大件快递，送到学十楼 305，有偿。",
  "attachmentIds": [31]
}
```

**成功响应**

```json
{
  "code": 0,
  "message": "发布成功",
  "data": {
    "requestId": 12
  }
}
```

**失败场景**

| 场景 | HTTP | code | message |
| --- | --- | --- | --- |
| 主题 / 类型 / 地域 / 描述为空或不合法 | 400 | 40001 | 参数校验失败（`data` 为字段错误映射） |
| 附件类型或大小不合法 | 400 | 40002 | 文件类型或大小不符合要求 |
| 附件不属于当前用户或已被其他需求引用 | 400 | 40001 | 参数校验失败 |
| 未登录 | 401 | 40102 | 请先登录 |

**实现要求**

1. 服务端再次校验标题、描述长度与类型、地域是否存在，不能只依赖前端；
2. `attachmentIds` 去重后按顺序写入 `sort_no`（从 1 开始）；
3. 绑定附件时需校验 `uploader_id = 当前用户` 且 `request_id IS NULL`；
4. 创建时间、修改时间由服务端生成，状态固定为 0。

同 4.4 的 `RequestDetailVO`，`message` 为“修改成功”。

| 场景 | HTTP | code | message |
| --- | --- | --- | --- |

```json
  }
}
```

**失败场景**

| 场景 | HTTP | code | message |
| --- | --- | --- | --- |
| 响应不存在 | 404 | 40403 | 响应信息不存在 |
| 非需求发布者 | 403 | 40302 | 只能操作自己发布的需求 |

### 4.12 上传附件

`POST /api/files`

- 鉴权：需要
- 请求格式：`multipart/form-data`，字段名 `file`
- 功能：上传单个图片或视频，返回文件信息；文件此时为“临时文件”，需在发布 / 修改需求时通过 `attachmentIds` 绑定

**请求示例**

```http
POST /api/files
Authorization: Bearer {token}
Content-Type: multipart/form-data; boundary=----Boundary

------Boundary
Content-Disposition: form-data; name="file"; filename="快递单.jpg"
Content-Type: image/jpeg

<二进制内容>
------Boundary--
```

**成功响应**

```json
{
  "code": 0,
  "message": "上传成功",
  "data": {
    "fileId": 31,
    "fileName": "快递单.jpg",
    "mediaType": "IMAGE",
    "contentType": "image/jpeg",
    "size": 184320,
    "url": "/api/files/31/content",
    "sortNo": 0
  }
}
```

**失败场景**

| 场景 | HTTP | code | message |
| --- | --- | --- | --- |
| 文件为空 | 400 | 40001 | 参数校验失败 |
| 类型或大小不符合要求 | 400 | 40002 | 文件类型或大小不符合要求 |
| 未登录 | 401 | 40102 | 请先登录 |

**实现要求**

1. 使用 UUID 作为存储文件名，保留原扩展名，目录按日期分片（如 `uploads/2026/11/`）；
2. 服务端校验 MIME 与文件头（避免伪造 `Content-Type`），大小上限见 1.6；

4. `mediaType` 依据 `content-type` 推导：`video/*` → `VIDEO`，其余 → `IMAGE`；

### 5.2 接口封装约定

1. 统一使用 `src/api/request.js` 的 `request()`，自动注入 JWT、解析 `{code,message,data}`、处理 40102 跳转；
2. 附件上传使用 `XMLHttpRequest` 以获得上传进度，同样解析统一响应结构，40102 时跳转登录页；
3. 所有“修改 / 删除 / 接受 / 拒绝”操作前均有 `window.confirm` 二次确认；
4. 后端返回的 `canModify` / `canDelete` / `canAccept` / `canReject` 直接决定按钮是否可用，前端不重复推导业务规则。

### 5.3 页面行为

| 页面 | 行为 |
| --- | --- |
| 请帮忙列表 `requests.html` | 进入时校验登录态；默认 `scope=mine` 查询自己发布的需求；支持状态、类型、地域、关键词筛选；分页（5/10/20 条，默认 10）；删除前二次确认，删除成功提示并刷新；已响应 / 已取消的需求“修改”“删除”按钮禁用并给出原因提示 |
| 发布 / 修改 `request-edit.html` | 无 `id` 参数为发布，有 `id` 为修改；修改时加载详情并在不可修改时禁用表单并说明原因；字典加载完成后才允许提交；标题 50 字、描述 1000 字实时计数；图片最多 6 张（单张 ≤ 5MB），视频最多 1 个（≤ 100MB），支持点击与拖拽上传、上传进度、移除；提交前二次确认，成功后跳转详情页 |
| 需求详情 `request-detail.html` | 展示主题、状态、类型、地域、时间、描述、图片画廊（点击放大）、视频播放、发布者信息；发布者可看到“我来也”响应列表（分页），可查看响应者信息、接受或拒绝响应（二次确认）；发布者可在可操作时修改 / 删除需求 |

### 5.4 状态与操作的前端表现

| 需求状态 | 状态徽章 | 修改按钮 | 删除按钮 | 响应区 |
| --- | --- | --- | --- | --- |
| 0 且无响应 | 已发布（绿色） | 可用 | 可用 | 显示，可接受 / 拒绝 |
| 0 且有响应 | 已发布（绿色） | 禁用（已有响应） | 禁用（已有响应） | 显示，可接受 / 拒绝 |
| -1 | 已取消（灰色） | 禁用（已取消） | 禁用（已取消） | 显示历史响应 |

### 5.5 表单校验规则

| 字段 | 规则 | 提示文案 |
| --- | --- | --- |
| title | 去除首尾空格后 1~50 字符 | 请输入需求主题 / 需求主题不能超过 50 个字符 |
| typeCode | 必选，须在字典中 | 请选择帮忙类型 |
| regionId | 必选，须在字典中 | 请选择地域 |
| description | 去除首尾空格后 1~1000 字符 | 请输入需求描述 / 需求描述不能超过 1000 个字符 |
| 图片 | JPG/PNG/WebP/GIF，单张 ≤ 5MB，≤ 6 张 | 仅支持 JPG / PNG / WebP / GIF 格式的图片 / 图片大小不能超过 5MB / 最多上传 6 个图片 |
| 视频 | MP4/WebM，≤ 100MB，≤ 1 个 | 仅支持 MP4 / WebM 格式的视频 / 视频大小不能超过 100MB |

前端校验仅用于提升体验，服务端必须做同样校验。

### 5.6 附件上传交互

1. 选择文件后立即上传（`POST /api/files`），上传成功才计入附件集合；
2. 上传中禁用提交与移除按钮，并展示整体进度（第 n/m 个、百分比）；
3. 用户移除“本次新上传”的附件时调用 `DELETE /api/files/{fileId}` 清理，失败不阻塞；
4. 修改需求时移除“已保存”的附件不立即调用删除接口，而是通过提交时 `attachmentIds` 的差异由服务端处理；
5. 提交顺序即 `sortNo` 顺序，首个图片作为列表封面。

### 6.4 业务规则汇总

1. 需求创建：状态固定 0，`create_time = update_time = 当前时间`；
2. 修改 / 删除的前置条件：发布者本人 + `status = 0` + `help_response` 中不存在该需求的任何记录；
3. 接受响应：需求发布者 + 需求 `status = 0` + 响应 `status = 0` + 该需求尚无 `status = 1` 的响应；接受后同一需求其余待接受响应自动置为拒绝，并写入 `help_success`；
4. 拒绝响应：需求发布者 + 响应 `status = 0`；
5. `scope=all` 只返回 `status = 0` 的需求；
6. 响应 / 附件的统计字段建议在查询时聚合，避免逐行查询；
7. 所有写操作加事务，接受响应需保证“响应状态 + 其他响应拒绝 + 成功明细”原子性。

### 6.5 附件存储

| 配置/约定 | 说明 |
| --- | --- |
| `bupthelper.upload.dir` | 附件根目录，默认 `./uploads` |
| 存储路径 | `{upload.dir}/yyyy/MM/{uuid}.{ext}` |
| 数据库记录 | 只存 `stored_name`，不存绝对路径 |
| 访问方式 | `GET /api/files/{fileId}/content` 读取流并回写 `Content-Type` |
| 临时文件清理 | 定时任务（如每小时）删除 `request_id IS NULL AND create_time < now - 24h` 的文件与磁盘文件 |

### 6.6 安全与校验

1. 服务端必须校验：标题与描述长度、类型与地域存在性、附件归属与数量、文件类型与大小；
2. 修改 / 删除 / 接受 / 拒绝必须校验当前用户身份与需求归属，禁止仅依赖前端隐藏按钮；
3. 排序字段、筛选字段使用白名单，防止 SQL 注入；关键词查询使用参数绑定；
4. 附件下载路径由 `fileId` 查询数据库得到，不接受客户端路径；校验规范化路径位于 `upload.dir` 内；
5. 日志不得记录完整附件内容；`api/files/*/content` 放行登录拦截器时需确认没有暴露其他 `/api/files` 接口。

### 6.7 拦截器配置调整

在 `WebConfig.PUBLIC_ENDPOINTS` 中新增：

```java
"/api/files/*/content"
```

其余 `/api/files/**`（上传、删除）仍需登录。

## 8. 测试要点

1. 分页：首页 / 末页 / 超出页码 / pageSize 边界（1、50、51）；
2. 筛选：类型、地域、关键词组合，关键词大小写与中文匹配；
3. 权限：非发布者修改 / 删除 / 查看响应列表 / 接受响应均返回 40302；
4. 状态：已取消需求不可修改、删除；已有响应的需求不可修改、删除（40902 / 40903）；
5. 附件：类型伪造、超大文件、超过数量上限、绑定他人附件均被拒绝；
6. 接受响应：并发接受两条响应只允许一条成功；接受后其余响应自动拒绝；`help_success` 有且仅有一条；
7. 删除需求后附件仍可访问、响应历史仍可查询；
8. 附件内容接口无需登录可访问，其他文件接口未登录返回 40102。
