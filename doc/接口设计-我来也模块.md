## 1. 通用约定

沿用请帮忙模块的通用约定（统一响应结构、JWT、分页 `PageResult<T>`、附件规则 1.6、时间格式等），此处仅补充“我来也”模块特有的内容。

### 1.1 业务状态码（在已有基础上新增）

| code | HTTP 状态码 | 含义 | 前端处理建议 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | 正常处理 `data` |
| 40001 | 400 | 请求参数校验失败 | 用 `data` 字段错误渲染表单项 |
| 40002 | 400 | 文件类型或大小不符合要求 | 在附件区域提示 |
| 40102 | 401 | 未登录 / 登录已过期 | 清理本地 token，跳转登录页 |
| 40302 | 403 | 只能操作自己发布的需求 | 顶部提示 |
| 40303 | 403 | 只能操作自己提交的响应 | 顶部提示 |
| 40402 | 404 | 需求不存在 | 提示并返回 |
| 40403 | 404 | 响应信息不存在 | 提示并刷新列表 |
| 40904 | 409 | 当前响应状态不允许该操作 | 提示并刷新列表 |
| 40905 | 409 | 该需求已接受其他响应 | 提示并刷新 |
| 40906 | 409 | 该需求已取消 | 提示并刷新 |
| 40908 | 409 | 不能响应自己发布的需求 | 顶部提示 |
| 40909 | 409 | 该需求已有人提供帮助，不能再响应 | 顶部提示 |
| 40910 | 409 | 你已对该需求提交过响应 | 顶部提示，引导查看“我的响应” |
| 50000 | 500 | 服务器内部错误 | 通用错误提示 |

### 1.2 状态定义（复用请帮忙模块 1.5）

| 响应状态 | statusName | 说明 |
| --- | --- | --- |
| 0 | 待接受 | 刚提交，等待需求发布者处理 |
| 1 | 同意 | 发布者已接受（`help_success` 写入成功明细） |
| 2 | 拒绝 | 发布者已拒绝 |
| 3 | 取消 | 响应者主动撤回 |

### 1.3 附件约定

与请帮忙模块完全一致（图片 ≤ 6 张/5MB、视频 ≤ 1 个/100MB、总数 ≤ 7）。响应附件与需求附件共用同一张表 `help_request_file`（`request_id` / `response_id` 二选一绑定，均为空表示临时文件），上传、访问、删除接口不变（`POST /api/files`、`GET /api/files/{id}/content`、`DELETE /api/files/{id}`）。

## 2. 数据模型

### 2.1 复用模型

`PageResult<T>`、`AttachmentVO`、`UserBriefVO`、`HelpTypeVO`、`RegionVO` 沿用请帮忙模块定义。

### 2.2 RequestSummaryVO 新增字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| myResponseCount | int | 当前登录用户对该需求提交的“未取消”响应数量，> 0 表示“我已响应” |

### 2.3 RequestDetailVO 新增字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| myResponseCount | int | 当前用户对该需求提交的“未取消”响应数量 |
| myResponseId | long \| null | 当前用户对该需求最近的响应标识（优先“待接受”），用于“查看我的响应”跳转；未响应时为 `null` |

### 2.4 MyResponseVO（“我的响应”列表项）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| responseId | long | 响应标识 |
| requestId | long | 需求标识 |
| status | int | 0 待接受 / 1 同意 / 2 拒绝 / 3 取消 |
| statusName | string | 状态中文名称 |
| description | string | 响应描述 |
| attachments | AttachmentVO[] | 响应图片 / 视频 |
| canModify | boolean | 当前用户能否修改（仅“待接受”） |
| canDelete | boolean | 当前用户能否取消（仅“待接受”） |
| createTime | string | 提交时间 |
| updateTime | string | 修改时间 |
| request | RequestSummaryVO | 所属需求摘要（主题、类型、地域、状态等） |

### 2.5 ResponseDetailVO（响应详情）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| responseId | long | 响应标识 |
| requestId | long | 需求标识 |
| status / statusName | int / string | 响应状态 |
| description | string | 响应描述 |
| attachments | AttachmentVO[] | 响应图片 / 视频 |
| canAccept | boolean | 需求发布者能否接受（待接受 + 需求已发布 + 尚无已接受响应） |
| canReject | boolean | 需求发布者能否拒绝（待接受） |
| canModify | boolean | 响应者能否修改（待接受） |
| canDelete | boolean | 响应者能否取消（待接受） |
| createTime / updateTime | string | 时间 |
| responder | UserBriefVO | 响应者信息 |
| request | RequestSummaryVO | 所属需求摘要 |

## 3. 接口清单

| 序号 | 接口名称 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 查询全部需求（参与优先） | GET | `/api/requests?scope=all&sort=myParticipation` | 复用请帮忙模块，新增排序与字段 |
| 2 | 查询我的响应 | GET | `/api/responses` | 分页 + 状态筛选 |
| 3 | 响应详情 | GET | `/api/responses/{responseId}` | 响应者 / 发布者 / 管理员 |
| 4 | 提交响应 | POST | `/api/responses` | “我来也” |
| 5 | 修改响应 | PUT | `/api/responses/{responseId}` | 仅待接受 + 本人 |
| 6 | 取消响应 | DELETE | `/api/responses/{responseId}` | 逻辑取消，状态置 3 |
| 7 | 接受响应 | PUT | `/api/responses/{responseId}/accept` | 需求发布者 |

## 4. 接口详情

### 4.1 查询全部需求（自己参与优先）

`GET /api/requests?scope=all&sort=myParticipation`

- 鉴权：需要
- 功能：查询平台全部已发布需求；`sort=myParticipation` 时“我已响应的需求”排在最前，其后按创建时间倒序

**请求参数**：同请帮忙模块 4.3（`typeCode`、`regionId`、`keyword`、`page`、`pageSize`），`scope=all`，`sort=myParticipation`。

**成功响应**：`PageResult<RequestSummaryVO>`，每个 `list` 项额外包含 `myResponseCount`。

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [
      {
        "requestId": 12,
        "title": "帮忙取一下快递",
        "typeName": "代购",
        "regionFullName": "北京市 · 北京市 · 海淀区",
        "status": 0,
        "responseCount": 2,
        "myResponseCount": 1,
        "canModify": false,
        "canDelete": false,
        "createTime": "2026-11-14 09:30:00"
      }
    ],
    "page": 1, "pageSize": 10, "total": 1, "totalPages": 1, "hasPrev": false, "hasNext": false
  }
}
```

**说明**：`myResponseCount` 仅统计“未取消”的响应（status ≠ 3），取消过的响应不计入“我已响应”。

### 4.2 查询我的响应

`GET /api/responses`

- 鉴权：需要，固定返回当前登录用户的响应
- 功能：查询自己提交的“我来也”响应；`status=1` 即“已被接受的响应”

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| status | int | 否 | 0 待接受 / 1 同意 / 2 拒绝 / 3 取消；不传表示全部 |
| page | int | 否 | 默认 1 |
| pageSize | int | 否 | 默认 10，范围 1~50 |
| sort | string | 否 | `createTime,desc`（默认）/ `createTime,asc` / `updateTime,desc` / `updateTime,asc` |

**成功响应**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [
      {
        "responseId": 5,
        "requestId": 12,
        "status": 0,
        "statusName": "待接受",
        "description": "我下午正好去驿站，可以顺路帮你取。",
        "attachments": [],
        "canModify": true,
        "canDelete": true,
        "createTime": "2026-11-14 10:05:00",
        "updateTime": "2026-11-14 10:05:00",
        "request": {
          "requestId": 12,
          "title": "帮忙取一下快递",
          "typeName": "代购",
          "regionFullName": "北京市 · 北京市 · 海淀区",
          "status": 0,
          "responseCount": 2,
          "myResponseCount": 1
        }
      }
    ],
    "page": 1, "pageSize": 10, "total": 1, "totalPages": 1, "hasPrev": false, "hasNext": false
  }
}
```

### 4.3 响应详情

`GET /api/responses/{responseId}`

- 鉴权：需要，响应者本人 / 需求发布者 / 管理员可查看
- 功能：查看某条“我来也”响应的具体信息（含所属需求摘要、响应者信息、附件）

**成功响应**：`ResponseDetailVO`（见 2.5）。

**失败场景**

| 场景 | HTTP | code |
| --- | --- | --- |
| 响应不存在 | 404 | 40403 |
| 非响应者 / 非发布者 / 非管理员 | 403 | 40303 |

---

### 4.4 提交响应

`POST /api/responses`

- 鉴权：需要
- 功能：对某条已发布需求提交“我来也”响应，状态置 0（待接受）

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| requestId | long | 是 | 需求标识 |
| description | string | 是 | 响应描述，去除首尾空格后 1~1000 字符 |
| attachmentIds | long[] | 否 | 附件标识数组，图片 ≤ 6、视频 ≤ 1、总数 ≤ 7；仅可绑定本人上传且未绑定的文件 |

**请求示例**

```http
POST /api/responses
Authorization: Bearer {token}

{
  "requestId": 12,
  "description": "我下午正好去驿站，可以顺路帮你取。",
  "attachmentIds": [31]
}
```

**成功响应**：`ResponseDetailVO`，`message` 为“响应提交成功”。

**失败场景**

| 场景 | HTTP | code |
| --- | --- | --- |
| 描述为空 / 过长、附件校验失败 | 400 | 40001 / 40002 |
| 需求不存在 | 404 | 40402 |
| 响应自己发布的需求 | 409 | 40908 |
| 需求已有人提供帮助（已有被接受响应） | 409 | 40909 |
| 已提交过待接受响应（同一需求） | 409 | 40910 |
| 需求已取消 | 409 | 40906 |

**实现要求**：同一用户对同一需求只允许存在一条“待接受”响应；取消 / 被拒绝后可重新提交。

---

### 4.5 修改响应

`PUT /api/responses/{responseId}`

- 鉴权：需要，仅响应者本人，且状态为“待接受”
- 功能：修改响应描述与附件集合（`attachmentIds` 表示修改后的完整集合）

**请求体**：同 4.4（忽略 `requestId` 字段）。

**成功响应**：`ResponseDetailVO`，`message` 为“修改成功”。

**失败场景**

| 场景 | HTTP | code |
| --- | --- | --- |
| 响应不存在 | 404 | 40403 |
| 非响应者 | 403 | 40303 |
| 状态不是待接受 | 409 | 40904 |

---

### 4.6 取消响应

`DELETE /api/responses/{responseId}`

- 鉴权：需要，仅响应者本人，且状态为“待接受”
- 功能：逻辑取消（`status = 3`），不物理删除；取消后可按 `status=3` 查询

**成功响应**

```json
{ "code": 0, "message": "响应已取消", "data": null }
```

**失败场景**：同 4.5。

---

### 4.7 / 4.8 接受、拒绝响应

`PUT /api/responses/{responseId}/accept`、`PUT /api/responses/{responseId}/reject`

与请帮忙模块 4.9、4.10 一致：需求发布者操作，接受后其余待接受响应自动置为拒绝并写入 `help_success`。

## 5. 前端对接说明

### 5.1 页面与模块划分

```
front/buptHepler
├── responses.html              我来也·全部需求（自己参与优先，分页 + 筛选）
├── my-responses.html           我的响应（状态筛选、分页、详情弹窗）
├── response-edit.html          提交 / 修改响应（含图片、视频上传）
├── request-detail.html         需求详情（非发布者展示“我来也 / 查看我的响应”入口）
└── src
    ├── api
    │   ├── responses.js        响应接口：submit / list / detail / update / cancel
    │   └── requests.js         复用 fetchRequests（scope=all&sort=myParticipation）
    ├── pages
    │   ├── responses.js        全部需求列表逻辑
    │   ├── my-responses.js     我的响应列表 + 详情弹窗 + 取消
    │   └── response-edit.js    响应表单 + 附件上传 + 提交 / 修改
    └── utils
        └── display.js          响应状态徽章（已存在）
```

### 5.2 页面行为

| 页面 | 行为 |
| --- | --- |
| `responses.html` | 默认 `scope=all&sort=myParticipation`；“我已响应”的需求带徽章并优先展示；每行“查看详情”“我来也”（未响应）/“查看我的响应”（已响应）；支持类型、地域、关键词筛选与分页 |
| `my-responses.html` | 状态筛选（全部 / 待接受 / 已接受 / 已拒绝 / 已取消）；每行展示所属需求、描述、状态、附件数；“查看”弹窗展示完整详情；仅“待接受”可“修改”“取消”，操作均有二次确认 |
| `response-edit.html` | 无 `responseId` 为提交（按 `requestId` 加载需求上下文），有 `responseId` 为修改（回填并校验可修改）；附件上传复用请帮忙模块交互；成功后跳转“我的响应” |
| `request-detail.html` | 非发布者展示“我来也”入口；已响应则展示“查看我的响应” |

### 5.3 表单校验

| 字段 | 规则 |
| --- | --- |
| description | 去除首尾空格后 1~1000 字符 |
| 图片 / 视频 | 同请帮忙模块（6 张 / 5MB、1 个 / 100MB、总数 ≤ 7） |

## 6. 后端实现说明

### 6.1 模块划分

| 组件 | 说明 |
| --- | --- |
| `HelpResponseService` | 响应提交、查询、详情、修改、取消、接受 / 拒绝 |
| `HelpResponseController` | `/api/responses` 全部端点 |
| `HelpRequestService` | 需求侧：新增 `summarize`（公开）、`myParticipation` 排序、`myResponseCount` / `myResponseId` 计算 |
| `HelpRequestRepository` | 新增 `findAllPublishedWithMyParticipation`（JPQL，`case when exists` 参与优先排序） |
| `HelpRequestFile` / 表 | 新增 `response_id` 列，需求 / 响应附件统一存储 |

### 6.2 数据表变更

`help_request_file` 新增 `response_id` 列（可空，与 `request_id` 二选一），并新增外键 `fk_help_request_file_response -> help_response(response_id)`。DDL 见 `back/buptHelper/db/init.sql`，应用启动时 `ddl-auto=update` 会自动补列。

### 6.3 业务规则汇总

1. 提交响应：需求已发布、非发布者、无已接受响应、本人无待接受响应；
2. 修改 / 取消：仅响应者 + 待接受状态；
3. 接受响应：发布者 + 待接受 + 无已接受响应；接受后其余待接受响应自动拒绝并写入 `help_success`；
4. 拒绝响应：发布者 + 待接受；
5. “自己参与优先”：`sort=myParticipation` 按“是否存在本人未取消的响应”降序、再按创建时间倒序；
6. `myResponseCount` / `myResponseId` 仅统计未取消（status ≠ 3）的响应。

### 6.4 测试要点

1. 提交 / 修改 / 取消 / 接受的完整状态流转；
2. 重复提交 → 40910；响应自己需求 → 40908；已接受需求再提交 → 40909；
3. 取消后重新提交、被拒绝后重新提交；
4. “我已响应”优先级排序与 `myResponseCount` 字段；
5. 附件：类型 / 大小 / 数量 / 归属 / 跨需求与跨响应引用校验；
6. 权限：非响应者修改 / 取消 → 40303；非发布者接受 / 拒绝 → 40302。
